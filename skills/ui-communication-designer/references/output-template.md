# Full Communication Review Contract

Use this shape for a multi-screen critique, redesign handoff, or explicit scored review. It is not required for a compact or copy-only response. Omit a field only when it is clearly outside scope.

## Workflow

1. State what the user is trying to accomplish, why it matters, what questions or hesitations they bring, the value of success, and any cost, commitment, or recovery concern.
2. Explain the task as a competent person would before choosing components. Lead with the goal, put necessary information before secondary detail, and ask the real decision directly.
3. Map the entry point, each user decision, system response, required information, commit points, exception and recovery paths, and details that can be deferred. Preserve non-sensitive input across backtracking and recoverable errors.
4. For each screen or step, define the communication job, discoverability, affordance, predicted outcome, feedback, and whether instruction is needed. Cover labels, navigation, defaults, progressive disclosure, errors, warnings, confirmations, and notifications.
5. Check that the focal point, scan path, primary action, endpoint, cost, consequences, data use, and recovery are clear before commitment.
6. Make each material recommendation state the supplied or observed problem, its effect on clarity, effort, trust, or recovery, the proposed change, expected improvement, and High, Medium, or Low priority.

Choose a component because it fits the decision. Prefer, in order: do not ask, infer safely, provide a safe default, ask later, then ask now only when necessary. Ask once and reuse information the product already has. Use hierarchy, grouping, order, and progressive disclosure before explanatory paragraphs. Avoid vague recommendations; explain the causal improvement.

When recommendations conflict, prefer comprehension, lower task effort, trust and risk reduction, a clear next step, simple scanning, platform convention, then visual polish.

## Finish Conditions

- The primary and recovery flows identify user decisions, system responses, and commit points where relevant.
- Screen and copy recommendations follow from supplied or observed evidence.
- In-scope title or main instruction, primary CTA, helper text, and error copy are rewritten; warning or confirmation copy appears only when needed.
- Unsupported evidence dimensions remain `not assessed`; totals appear only with all 12 dimensions supported.
- The result ends with the highest-leverage change instead of generic design principles or unauthorized follow-on work.
